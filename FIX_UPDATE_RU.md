# DLPapp 2.0.3: исправление обновления GUI

Основа: исходники GUI 2.0.2 из последнего архива. CLI не изменён.

## Почему понадобилось исправление

В 2.0.2 обновлятор наследовал переменные старого PyInstaller/runtime и изменённый путь поиска DLL. Ошибки записи подтверждения запуска молча игнорировались. Это согласуется с наблюдением, что запуск со сбросом среды помог, но не устанавливает точную причину каждого сбоя на других ПК.

## Что изменено

- PowerShell запускается с очищенной средой и стандартным путём поиска DLL; PYINSTALLER_RESET_ENVIRONMENT=1 задаётся явно.
- Перед новым EXE скрипт снова очищает старое состояние runtime.
- Каждый запуск обновления имеет уникальные nonce, acknowledgement и backup; оставшийся backup прежней попытки не блокирует следующий запуск и не удаляется автоматически.
- Успех требует подтверждения версии, токена, EXE и существования нового GUI-процесса. Успешное завершение короткого native launcher не считается успехом GUI.
- GUI повторяет запись acknowledgement при временной ошибке, вместо молчаливой потери запроса. Формат остаётся совместим со старым обновлятором без токена.
- Отведено 300 секунд на запуск новой версии (вместо 180). Это запас для первого запуска, не замена исправлению среды.
- Новый EXE сверяется по SHA256 до и после копирования. Скачанный файл остаётся доступным для восстановления.
- При сбое новый EXE перемещается в отдельный .dlpapp-failed-...; старый возвращается из backup. Если EXE заблокирован, резервная копия сохраняется и журнал объясняет, что автоматический откат не завершён. Новое приложение не уничтожается принудительно.
- Mutex предотвращает одновременную работу двух установщиков в сеансе Windows.
- Настройки, история, DDownloads и runtime не удаляются.

## Первое обновление на ПК с 2.0.0–2.0.2

Самый предсказуемый путь — заменить EXE вручную после сборки 2.0.3. Старый установленный обновлятор невозможно исправить только публикацией нового релиза. Подтверждение 2.0.3 совместимо со старым скриптом, но это не гарантирует исправление его запуска.

1. Закройте приложение через «Выход» в трее. Дождитесь завершения уже запущенной попытки обновления.
2. Сохраните старый EXE отдельно, скопируйте новый 2.0.3 на его место.
3. Не удаляйте %LOCALAPPDATA%\DLPapp: здесь находятся настройки и история.
4. Запустите новый EXE, проверьте версию, никнейм, язык, папку и одну загрузку.
5. Для следующих обновлений будет использоваться исправленный обновлятор.

Не отключайте антивирус ради установки. Ошибки Defender/блокировка EXE требуют отдельной проверки и не гарантированно устраняются этим изменением.

## Проверка сборки

Скопируйте содержимое папки DLPapp из ZIP в корень проекта с заменой файлов, сохранив LICENSE и папку cli. Запустите build_windows.bat. Готовые файлы: dist\DLPapp.exe и dist\DLPapp.exe.sha256.

В Windows теперь автоматически выполняются PowerShell-тесты на временных файлах:
- успешная замена и подтверждение нового процесса;
- неверный SHA256 (старый EXE остаётся на месте);
- отсутствие подтверждения (старый EXE восстанавливается, новый сохраняется отдельно).

Тест создаёт маленький управляемый Windows EXE в отдельной временной папке. Установленные DLPapp.exe и настройки пользователя он не меняет. Если защитное ПО блокирует тестовый файл, не обходите блокировку: сохраните точное обнаружение для анализа.

На Linux прошло 43 теста; GUI и native Windows-тест пропущены. Windows-сборка, фактический restart и уведомления в этой среде не проверялись. Не публикуйте новую сборку как проверенную, пока Windows-проверки не завершены.

## Если ошибка повторилась

Отправьте тексты файлов:
- %LOCALAPPDATA%\DLPapp\update-error.log
- %LOCALAPPDATA%\DLPapp\update-install.log
- %LOCALAPPDATA%\DLPapp\update-startup.log

Также укажите исходную и целевую версии. Не запускайте старые install-*.ps1 повторно. Не удаляйте backup, .failed и JSON настроек наугад.

## Проверка уведомлений в 2.0.3

В настройках → Общие нажмите «Проверить уведомление». Должен появиться баннер Windows. Если показ не подтверждён, приложение откроет резервное сообщение в течение 10 секунд.

Затем скачайте короткое видео и нажмите «Скрыть и уведомить по завершении». Проверьте завершение загрузки, уведомление и возврат окна нажатием на значок в трее. Повторите с включённым режимом Windows «Не беспокоить»: при отсутствии подтверждения баннера должно открыться окно с результатом.

Журнал: `%LOCALAPPDATA%\DLPapp\notifications.log`. Нативный показ баннеров требует проверки на Windows; тесты здесь проверяют отслеживание доставки и резервное сообщение.
